# Telegram-бот и серверная синхронизация — дизайн

Дата: 2026-10-14. Статус: утверждена, реализована по плану `docs/superpowers/plans/2026-10-14-telegram-bot-backend.md`.

Это подпроект 1 из трёх. Два других строятся поверх него и в эту спеку **не входят**:

1. **Этот документ:** сервер, команды бота, синхронизация с мини-аппом.
2. Живая речь («Потратил 1000 на еду» превращается в `/spent 1000 еда`).
3. ИИ-бухгалтер (короткий отчёт и график по запросу без входа в мини-апп).

## 1. Цель и критерии успеха

Вести учёт прямо из чата с ботом, а мини-апп использовать для просмотра и настройки. Данные у бота и мини-аппа общие.

Успех, когда выполняется всё:

- `/spent 500 такси` в чате создаёт расход, и он появляется в мини-аппе после его открытия или возврата на экран.
- `/income 50000 зарплата` создаёт доход так же.
- `/balance`, `/month`, `/last`, `/undo` показывают данные, совпадающие с мини-аппом.
- Кнопка «📥 Добавить выписку» в чате открывает мини-апп сразу на выборе файла, минуя главный экран.
- Старые данные из `localStorage` один раз переезжают на сервер, ничего не теряется и не дублируется.
- Чужие данные прочитать нельзя ни через бота, ни через API.

## 2. Допущения и решения

| Решение | Значение |
|---|---|
| Хостинг | Cloudflare Workers + база D1 |
| Пользователи | Несколько человек, у каждого свои данные (разделение по Telegram ID) |
| Допуск | Открыт для всех. Защита: лимиты и аварийный «рубильник» (раздел 7) |
| Источник правды | Сервер (D1). `localStorage` остаётся кэшем и режимом без Telegram |
| Выписка | Кнопка «📥 Добавить выписку» в чате открывает мини-апп на экране выбора файла. Разбор файлов остаётся в браузере |
| Тип кнопки | Inline-кнопка Web App под сообщениями бота (у такой кнопки приходит `initData`; у кнопки-клавиатуры он пустой, см. раздел 5) |
| Дата | Только календарный день, без часовых поясов и настроек |
| Язык кода | JavaScript (ES-модули) с JSDoc, как и остальной проект |

Вне Telegram (GitHub Pages в обычном браузере) приложение работает локально, как сейчас.

## 3. Архитектура

Новая папка `worker/` в репозитории. Один Worker, четыре обязанности:

- **Вход Telegram** `POST /telegram/webhook`: проверка секретного заголовка, разбор обновления, команды.
- **API мини-аппа** `/api/...`: проверка подписи `initData`, данные пользователя.
- **База D1:** общий слой запросов.
- **Лимиты и защита от повторов.**

```
worker/
  wrangler.toml
  migrations/0001_init.sql
  src/index.js        маршрутизация: webhook, api, 404, CORS
  src/telegram.js     вызовы Bot API (sendMessage, answerCallbackQuery)
  src/commands.js     разбор и обработчики команд
  src/parse.js        разбор команды и суммы
  src/auth.js         проверка initData и секрета вебхука
  src/api.js          обработчики /api
  src/validate.js     проверка входных данных
  src/db.js           запросы к D1
  src/core.js         addOperation, getReport — общее ядро (см. раздел 9)
  src/categories.js   правила автокатегорий и настройки по умолчанию
  src/format.js       деньги, даты, экранирование HTML
  src/limits.js       лимиты запросов
  test/*.test.js
  package.json
js/api.js             новый: синхронизация мини-аппа с сервером
```

Мини-апп: `js/telegram.js` теряет код CloudStorage (`cloudRead`, `cloudWrite`, `applyCloud`, `initCloudSync`), синхронизация переходит в `js/api.js`.

## 4. Модель данных (D1)

```sql
CREATE TABLE users (
  id           INTEGER PRIMARY KEY,           -- Telegram user id
  settings     TEXT    NOT NULL DEFAULT '{}', -- тот же JSON, что settings в приложении
  month_target REAL    NOT NULL DEFAULT 100000,
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL
);

CREATE TABLE operations (
  id         TEXT    NOT NULL,
  user_id    INTEGER NOT NULL,
  type       TEXT    NOT NULL CHECK (type IN ('income','expense')),
  name       TEXT    NOT NULL,
  amount     REAL    NOT NULL CHECK (amount > 0),
  category   TEXT,
  date       TEXT    NOT NULL,                -- ISO, как в приложении
  source     TEXT,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (user_id, id)
);
CREATE INDEX idx_ops_user_date    ON operations (user_id, date);
CREATE INDEX idx_ops_user_created ON operations (user_id, created_at);

CREATE TABLE processed_updates (update_id INTEGER PRIMARY KEY, at INTEGER NOT NULL);
CREATE TABLE rate_limits (user_id INTEGER NOT NULL, scope TEXT NOT NULL, minute INTEGER NOT NULL,
                          count INTEGER NOT NULL, PRIMARY KEY (user_id, scope, minute));
```

- Формат операции остаётся таким же, как в приложении: `{id, name, amount, type, category, date, source}`.
- Дата хранится как `YYYY-MM-DDT12:00:00.000Z`. Полдень по UTC не даёт дате «уехать» в любом часовом поясе от UTC-12 до UTC+11, а `startsWith('2026-10')` в приложении продолжает работать.
- Суммы суммируются как `ROUND(SUM(amount), 2)`, чтобы не копить ошибки дробей.
- Удаление всех данных пользователя делается явными `DELETE` по обеим таблицам, а не каскадом.

## 5. Команды бота

Работает только в личных чатах (`chat.type = private`). В группах бот молчит. Ответы бота на русском, в HTML-режиме Telegram, весь пользовательский текст экранируется.

| Команда | Что делает |
|---|---|
| `/start` | Создаёт пользователя, приветствует, показывает кнопки «📊 Открыть приложение» и «📥 Добавить выписку» |
| `/help` | Список команд с примерами и те же две кнопки |
| `/spent <сумма> [описание]` | Добавляет расход |
| `/income <сумма> [описание]` | Добавляет доход (например, `/income 50000 зарплата`) |
| `/balance` | Доход, расход, остаток за месяц; остаток за всё время; прогресс к цели месяца и главной цели; под ответом кнопки приложения и выписки |
| `/month` | Расходы текущего месяца по категориям (по убыванию, с процентами) |
| `/last [N]` | Последние N операций (по умолчанию 5, максимум 20) |
| `/undo` | Удаляет последнюю добавленную операцию (по `created_at`) и сообщает, что удалено |
| `/statement` | Присылает сообщение с кнопкой «📥 Добавить выписку» (на случай, если нужная кнопка уже прокручена вверх) |
| `/deleteall` | Удаляет все данные пользователя после подтверждения кнопками |

**Разбор `/spent` и `/income`.**
- Сумма: `500`, `1 500`, `1500,50`, `1500.50`. Должна быть больше 0, не больше 999 999 999.99, не больше двух знаков после запятой.
- Описание необязательно. Категория выбирается по порядку: совпадение описания (без учёта регистра) с категорией из настроек пользователя; иначе правила автокатегорий (те же, что при импорте выписок); иначе «Прочее» (если такой категории нет, первая из списка).
- Название операции: описание, а при пустом описании название категории. Если описание совпало с категорией, берётся её каноническое написание.
- Дата: сегодня, только календарный день, без часовых поясов и настроек. Чтобы «сегодня» не съезжало на сутки между 00:00 и 03:00 по Москве, день определяется по UTC+3 одной константой в коде (в базе и настройках пояса нет).

**Ответ на добавление:** «✅ Расход 500 ₽ · Транспорт · такси. Остаток за месяц: 94 480 ₽» и кнопка «↩️ Отменить». Кнопка удаляет именно эту операцию (`callback_data = undo:<id>`).

**Неверный формат:** короткая подсказка с примером, операция не создаётся. Неизвестная команда или не-текст: подсказка «/help».

**Кнопка «📥 Добавить выписку».** Это inline-кнопка типа Web App с адресом `APP_URL?action=import`. Она показывается под сообщениями `/start`, `/help`, `/balance` и `/statement`, рядом стоит «📊 Открыть приложение» (адрес `APP_URL`).

- **Почему inline, а не кнопка-клавиатура:** по документации Telegram, у мини-аппа, запущенного с кнопки-клавиатуры (постоянная панель под полем ввода), данные `initData` пустые. По ним приложение входит на сервер и понимает, что оно в Telegram, поэтому такая кнопка сломала бы синхронизацию. У inline-кнопки `initData` приходит.
- **Что происходит по нажатию:** мини-апп открывается и, увидев `action=import`, сразу показывает окно «Загрузить выписку» с большой кнопкой «Выберите файл», а не главный экран. Само окно выбора файла Telegram и браузеры не разрешают открыть без касания, поэтому в мини-аппе нужно нажать эту кнопку один раз.
- **Дальше:** работает существующий импорт: предпросмотр, категории, защита от дублей, форматы CSV, Excel и PDF.

## 6. API мини-аппа

Формат ответа везде один: `{ "success": bool, "data": ..., "error": "..." | null }`.
Авторизация: заголовок `Authorization: tma <initData>`.

| Метод и путь | Назначение |
|---|---|
| `GET /api/data` | Операции, настройки, цель месяца пользователя |
| `POST /api/sync` | Пакет изменений: `{ upsert: [операции], remove: [id], settings?, monthTarget? }` |
| `DELETE /api/data` | Удалить все данные пользователя |

Один эндпоинт `sync` заменяет набор отдельных: он атомарный (один `batch` в D1) и подходит и для обычных изменений, и для первой миграции.

**Проверки входных данных** (на сервере, всегда): `type` из двух значений; `amount` в допустимых пределах; `name` до 200 символов; `category` до 40; `date` по шаблону ISO; в `upsert` не более 500 операций за запрос; в списке категорий не более 50 штук по 40 символов; тело запроса не больше 1 МБ. При нарушении ответ 400 с понятным текстом.

**CORS:** разрешён только адрес сайта на GitHub Pages (`ALLOWED_ORIGIN`), без `*`; обрабатывается `OPTIONS`.

## 7. Безопасность и лимиты

- **Webhook:** заголовок `X-Telegram-Bot-Api-Secret-Token` сравнивается с `WEBHOOK_SECRET` за постоянное время. Не совпало: 401.
- **initData:** подпись проверяется по схеме Telegram (HMAC-SHA256, ключ получается из токена бота), сравнение за постоянное время; `auth_date` не старше 24 часов; `user.id` берётся только из проверенных данных.
- **Секреты** (`BOT_TOKEN`, `WEBHOOK_SECRET`) лежат только в настройках Cloudflare (`wrangler secret`). В репозитории их нет: репозиторий публичный.
- **Лимиты:** 30 запросов в минуту на пользователя (бот и API вместе), до 20 000 операций на пользователя, до 500 операций в одном `sync`. При превышении: понятное сообщение, операция не выполняется.
- **Повторы от Telegram:** изменяющие команды выполняются одним `batch`: запись в `processed_updates` + запись операции. Повторное обновление с тем же `update_id` пропускается, операция не дублируется. Записи старше суток удаляются попутно.
- **Аварийный рубильник:** необязательная переменная `ALLOWLIST` (список Telegram ID). Если она задана, работают только эти пользователи. Включается, если открытый бот начнёт упираться в бесплатные квоты Cloudflare.
- **Ошибки:** детали пишутся в лог Worker, пользователю уходит нейтральный текст без внутренностей. Webhook отвечает 200 на обработанное и проигнорированное, 500 на непредвиденные сбои базы (Telegram повторит, а повтор безопасен).

## 8. Синхронизация в мини-аппе (`js/api.js`)

Работает только внутри Telegram (есть `initData`). Вне Telegram файл ничего не делает.

- **Старт:** `GET /api/data` (таймаут 8 с). Успех: состояние заменяется данными сервера и кэшируется в `localStorage`. Ошибка: приложение работает с кэшем и показывает тост «Нет связи, изменения сохранятся позже».
- **Изменения:** по событию `money:changed` (оно уже генерируется в `save()`) клиент считает разницу между текущим состоянием и последним снимком сервера (по `id`: добавлены, изменены, удалены; настройки отдельно) и отправляет её в `POST /api/sync`. При успехе снимок обновляется. При сбое снимок не трогается, и разница пересчитается при следующем изменении или запуске. Отдельная очередь не нужна.
- **Возврат в приложение** (`visibilitychange`): сначала отправляется накопленная разница, потом `GET /api/data`. Так операции, добавленные ботом, появляются без перезапуска.
- **Конфликты:** побеждает последняя запись по каждой операции и по настройкам. Для личного учёта этого достаточно.
- **Первая миграция** (флаг `syncedOnce` в `localStorage` не стоит): операции объединяются по `id` (локальные, которых нет на сервере, загружаются пачками по 100). Настройки: если на сервере они равны значениям по умолчанию, берутся локальные; иначе серверные. Затем флаг ставится. Из CloudStorage данные не читаются: `initCloudSync` и так зеркалил их в `localStorage` при каждом запуске.
- **`?action=import`:** открывает окно «Загрузить выписку» с кнопкой «Выберите файл» (раздел 5). Параметр читается из `location.search` один раз при старте и после открытия окна убирается из адреса, чтобы обновление страницы не открывало его снова.

## 9. Общее ядро для следующих подпроектов

Чтобы живая речь (подпроект 2) и ИИ-бухгалтер (подпроект 3) не дублировали логику, команды работают через две функции в `src/core.js`:

- `addOperation(env, userId, { type, amount, text, date? })` возвращает `{ operation, monthBalance }`.
- `getReport(env, userId, { from, to })` возвращает суммы по типам и категориям, динамику по месяцам.

Подпроект 2 будет только превращать фразу в вызов `addOperation`, подпроект 3 читать через `getReport`.

## 10. Тестирование

- **Сервер:** `vitest` с пулом `@cloudflare/vitest-pool-workers` (D1 поднимается локально). Покрытие `worker/src` не ниже 80%.
- **Что покрывается:** разбор суммы и команд (все форматы, граничные и неверные значения); определение категории; проверка подписи `initData` (верная, подделанная, просроченная); подсчёт баланса и отчётов; проверки входных данных; лимиты; защита от повторов (одно обновление дважды даёт одну операцию); авторизация (чужие данные недоступны); `/undo` и кнопка «Отменить».
- **Мини-апп:** автоматических тестов во фронтенде нет. Проверяется вручную в Telegram по чек-листу: первая миграция, добавление через бота и появление в апп, обратное направление, работа без сети, `/statement`.

## 11. Развёртывание

От пользователя понадобятся: аккаунт Cloudflare, бот от @BotFather (токен кладётся в настройки Cloudflare самим пользователем, в чат и репозиторий не присылается), адрес сайта на GitHub Pages.

Шаги: создать базу D1, применить миграцию, задать секреты и переменные (`APP_URL`, `ALLOWED_ORIGIN`, при необходимости `ALLOWLIST`), задеплоить Worker, вызвать `setWebhook` (с `secret_token`), `setMyCommands` (меню команд на русском) и `setChatMenuButton` (кнопка мини-аппа). Всё это описывается в README.

## 12. Известные компромиссы и риски

- **Открытый бот:** бесплатные квоты Cloudflare (в частности, число записей в D1 в сутки) можно исчерпать массовым спамом. Смягчают лимиты и `ALLOWLIST`.
- **Два источника правил:** правила автокатегорий и настройки по умолчанию дублируются в `worker/src/categories.js` (сайт и сервер собираются по-разному). Нужно менять в обоих местах.
- **Фильтр `accept` на кнопке выписки** убран в предыдущем шаге как гипотеза исправления проблемы Telegram (окно выбора файла не открывалось). Она пока не подтверждена. Если окно по-прежнему не открывается, `/statement` в таком виде тоже не поможет, и нужен другой способ выбора файла.
- **«Сегодня» в боте** определяется по UTC+3 без настройки. Пользователю из другого пояса день может показаться сдвинутым в несколько ночных часов. Если это понадобится, дату можно будет указывать в команде явно.
- **Конфликты** решаются «последняя запись побеждает». При одновременном редактировании одной операции с двух устройств часть правок теряется.
- **Суммы** хранятся как `REAL` для совместимости с приложением; точность два знака обеспечивается округлением при записи и суммировании.
